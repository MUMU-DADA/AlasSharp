# 上游引擎重写：目标、边界与验证

最终目标是 C# 执行全部非视觉逻辑，Python 只保留确有必要的 CV/OCR 桥接。当前产品入口已整体切换到 Alas.Engine，旧 Core/Python 游戏执行路径已退役；完整业务域和规则仍未迁完，不能称为重写完成。迁移已是明确目标，不再以“是否值得替换”的评估作为终点；现有正确性与真实路径门槛用于验证替换，不用于永久维持 Python 业务。当前阶段和缺口以[迁移路线](architecture-roadmap.md)为准。

前十四章五十六份可执行规则现直接编译为 C# 类。规则保留 Config 继承、舰队角色、道路组、战斗分派和章节自身钩子；公共道路组合、规模筛选、谜题拾取、双舰队占位与首段路障在同一 Engine 状态和战斗链执行。第八章保留实时谜题计数条件、分开的道路组、当前舰队先清路与原生覆盖层；三种相机倍率经 EngineSession 工厂应用，不在适配层按地图分支。第十章保留二队推进/占位、道路短路及 BOSS 钩子，10-2 的显式检测后端和固定校准由通用配置进入实际相机；9-1/10-2 的校准几何及寻边首手势已用原生投影截图、实际 EngineSession/纯 CV/模拟 ADB 对照。第十一、十二章保留独立 BOSS 清路返回语义、镜头恢复预设和补给门控，第十二章的检测配置和相机倍率由普通 Config 继承。第十三章保留按类型/规模过滤与保留数量、Siren 优先和补给顺序；公共过滤器在 C# 中执行，四关配置/钩子直接编译。目标被另一舰队占用的交互仍明确拒绝。可执行规则不经过 JSON 计划，也不调用 Python 业务；新增 Python 只在离线测试执行上游方法。288,660 项规则对拍及选敌、配置、相机/模拟 ADB、组合与失败验证见路线，没有新 Engine 实机通关证据。1,370 份 MAP 声明仍不等于全部 Campaign 已可运行。

第十四章新增灯塔、照明弹和显式舰队移动的 C# 操作，拾取物不计谜题；14-4 的 OVERRIDE 出生覆盖在地图初始化阶段应用，14-2 保留双舰队拾取与移动顺序。四服配置、32 组拾取轨迹、四关合成组合和失败边界均通过离线对照；没有新 Engine 真机通关证据。

第三章保留配置继承、检测参数与经验页覆写，二队推进、救援和指定舰队默认战斗均接入同一 C# 状态与移动链。推进按当前成本排序、二队可达性选择并在确认移动后切回；救援只清除真实可达的最少阻敌。补给路过不伪造弹药恢复，失败和回合中断不伪造切队完成。第三章本身将 BOSS 固定为一队，公共二队分支以独立原生对照验收；具体覆盖及未完成项见路线。

第四、五章保留已观察 BOSS 的可达性判断、道路短路与候选出生格搜索；没有 BOSS 观察时不伪造目标。Campaign 类属性以 Overlays 独立于 Config 迁移，第四章的伏击/空袭阈值由 EngineSession 传入统一探测及等待；其寻敌透明度字段在上游已不参与判断，只保留声明，识别仍用 luma 模板。四服真实纯 CV 颜色、原生判断/计时和八关合成战役验证见路线；产品不依赖新增的测试 Python oracle。

心情恢复与消耗现由 Engine 的 EmotionRules / CampaignEmotion 执行，EngineProfileStore 读写独立的 device/campaign 状态，EngineSession 连接入口门控、地图等待与战斗加载扣减；Python 仅在离线 oracle 中执行原生心情代码以核对语义。规则源码和状态合同记录来源哈希，不引入导出计划或解释器。计算模式不再被强制替换为 ignore；持久化、零动作延后与失败工件的行为见[任务文档](tasks.md)，已验证范围及长期重启/周期调度缺口见[路线](architecture-roadmap.md)。

地图准备、周回与双倍书现由 CampaignMapPreparation 和 CampaignPreparationRules 管理，复用既有纯 CV 测量及通用 Switch，不新增 Python 业务或 JSON 解释。章节 Config 与本次出击观测分离，周回覆盖在配置之后应用，控制 loop 地图/出生及机制；已确认双倍书连接心情等待和扣减，未知状态不能假定单倍。图内 resume 缺少先前倍率观察，计算模式拒绝，完整 campaign_run 通过准备页取得证据。完整成就/剧情覆盖、自动寻敌调度和全部章节尚未迁完；原生轨迹、四服 CV 与模拟 ADB 验证范围见路线，无新增真机通关结论。

BOSS 路障和战中舰队切换现由 MapRoadblocks、CampaignMapCombat 与 CampaignFleetSwitcher 直接执行。最少阻敌与原生枚举优先级保持一致，搜索不再污染权威成本场，出击只选真实可达的阻敌；舰队编号确认后重定位、读取 HP/等级并配置策略。部分切换失败也保存证据，不沿用旧舰队身份或相机。Python 新增内容仅为测试项目的原生搜索 oracle，产品视觉 worker 不增业务能力；语义修正、离线范围及未完成分支见[路线](architecture-roadmap.md)。

血量状态直接由 C# `FleetHealthState` / `FleetHealthReader` 管理，纯视觉 `color_bars` 只返回给定图像区域与颜色的色条长度，不接收舰队、服务器或撤退规则。首次读取的有船掩码按逻辑舰队保留，进图初始化与战后读取在 Engine 会话内执行。低血量判断位于地图移动之前，撤退由独立 C# 流程处理并使用冻结合同的 `withdrawn` 结果；读取失败不继续该次移动。战斗准备现由 C# CombatHealthPreparation 消费加权 HP，决定前排换位和紧急维修；纯视觉 worker 无新增业务操作。完整等级停止调度、战中舰队调度与新引擎实机结算仍未完成。

等级读取同样由独立 Engine 管理：`FleetLevelRules` 给出六槽区域、四服模型和像素预处理参数，`FleetLevelReader` 在地图帧上完成六槽读取，`FleetLevelState` 维护战前基线与原生到级/LV32 标记。视觉桥不接收服务器或“等级”业务操作，只执行通用亮度恢复、背景去除、前缀裁剪和模型推理；数字解析、触发条件和权威状态均在 C#。到级标记是外层调度依据，不能代替结算或立即撤退；完整连续出击调度仍未交付。

换位、维修规则和动作直接迁自 `HPBalancer`、`Combat.combat_preparation` 与 `Control.drag`。启用血量平衡才执行换位/维修；锁定舰队只禁止换位。当前设备后端保留原生 ADB 的 500ms 滑动和目标区域补点，不能据此宣称已实现 minitouch 等手势或游戏内换位已成功。维修保留确认优先、战力非零等待和彩色模板稳定等待，再检查按钮及 HP；非致命稳定超时仍按原生继续，但保存 `Stable=false`。HP 数组不会因点击或拖动而被推断更新，任务级 `combat-health.json` 和动作日志记录已请求/已完成输入、依据帧及等待观测，失败也保存。完整验证范围见迁移路线；新增 Python 文件仅在测试项目执行离线上游真值，不进入产品依赖。

## 目标与边界

航母谜题由 MapCarrierHandler / MapEnemySearching 在 C# 中识别、计数和等待，确认移动后由 MapScanner 的 carrier 模式补扫海面增援，再沿普通清敌链执行；没有新增产品 Python 操作或地图特例。新增 Python 文件仅在测试项目调用原生方法和生成图像夹具。原生计时、后续回合/战斗计数、失败状态与组合证据见[路线](architecture-roadmap.md)；第三章已通过直接编译的规则启用/关闭该公共能力，实机出击仍未验收。

伏击公共流程现由 MapAmbushHandler、MapAmbushInfo 与 CombatFlow 执行，C# 持有按钮选择、信息条结果、等待、战斗和恢复语义；视觉 worker 只对图像/模板执行通用数值像素变换。伏击战果独立保存，不充当地图敌人击破或通关证据，覆盖层与仅按钮入口的读取/补点差异保持原生行为。原生处理顺序、计时、地图记账与四服模板对拍范围见[路线](architecture-roadmap.md)，未使用旧 Core 或 Python 业务回退，也无新增实机验收。

诱饵流程已直接接入 CampaignMapCombat / MapMovement：战后普通扫描使用原生 decoy 模式，调用方用 C# 枚举保留战斗预期，普通 combat 的空目标在延迟确认后清除并重新选敌，不计战斗或弹药消耗。BOSS/塞壬/堡垒及无战果异常仍各按原合同处理，回合重扫和十次分派上界保持；没有逐地图假目标表或 Python 执行转发。80 条上游到达轨迹、扫描模式门控和完整 C# 合成战役的验证边界见[路线](architecture-roadmap.md)。

BOSS 出生恢复现由 MapCombatRecovery 调用当前编译 CampaignRule 的 RefocusBossAsync，MapCamera 直接完成原生刷新、必要预设滑动、边缘恢复和返回原机位；空 HP 重读仍由 C# 会话处理。所有规则与动作均在 Engine 内执行，新增 Python 仅为测试项目的原生对照。只有胜方战斗返回地图触发，地图计数在到达确认后提交；原始出生表门控、失败边界、112 条相机轨迹与实际章节钩子验证见[路线](architecture-roadmap.md)，不构成实机结算验收。

塞壬同格救援与弹跳敌人探查已由 CampaignMapCombat 直接执行，使用现有舰队切换、相机、路径、到达、战斗和重扫组件。保持原生角色门控、整条路线访问、重叠标志、13 次上限及回合异常顺序；救援须有胜方战斗，战后扫描失败不得复用部分状态。新增 Python 只在测试项目运行原生方法作离线对照，没有产品 Python 业务或中间规则转换。188 条原生轨迹、两个合成战役及明确拒绝的移动恢复边界见[路线](architecture-roadmap.md)，不扩大可执行章节或实机结论。

迷宫等待已接入独立战役路点：使用声明生成的邻格及原生筛选顺序移动，按相位切换重新分派，复用 C# 到达、战斗、补给确认和移动敌人重扫。当前舰队标记选项也直接进入到达规则并保留 BOSS 例外；没有新增产品 Python 业务或逐地图路线。原生 432 条 goto/_goto 对拍及实际合成战役范围见[路线](architecture-roadmap.md)。支持公共流程不代表全部迷宫章节已具备可执行 Campaign，也不代表真实出击通过。

移动敌人的出生回合、动画等待、敌人重扫和遮挡追踪已由 MapRounds / MapMovableScan 执行，EngineSession 直接连接现有扫描器与战役重新分派；舰队步数按原生角色映射进入路径分段。匹配使用多项式算法保留上游评分优先，假设敌人可达性不改写舰队成本。新增 Python 仅为测试项目的原生 oracle，产品视觉 worker 没有增加业务操作。完整离线范围、同分匹配边界和特殊移动缺口见[路线](architecture-roadmap.md)，不代表新引擎实机动态地图或全部章节通过。

陆基机关执行也已进入同一 C# 战役链：类型化规则可指定候选格，通用移动等待原生机关动画时长并确认到达，然后解除关联触发点/阻挡、刷新成本并重新分派。普通移动、已知战斗和物品谜题复用现有到达与结果合同，不新增 Python 业务、地图特例或独立机关脚本。原生真实方法的离线调用及合成战役验证范围见[路线](architecture-roadmap.md)；移动敌人公共流程见上文，迷宫公共等待见上文，全部活动规则仍未迁完。

地图目标判断与停止现由 CampaignObjectives / CampaignAchievement 执行，星级覆盖传入 C# 战役分派，取消进图并观察返章节页后才更新绑定任务的关卡或启用状态。全清的塞壬/堡垒选择、第二舰队成本选敌及最终堡垒释放机关阻挡进入通用地图链，不调用 Python 业务或静态 JSON 计划。规则对拍、真实会话合成回放和失败工件范围见[路线](architecture-roadmap.md)；写回下一关不表示该关已迁移，跳过不等于通关，完整调度与动态地图仍未交付。

船坞容量处理已直接迁为 `RetirementRules`、`RetirementDock`、`RetirementHandler` 与 `CampaignInterruptions`。一键和旧式退役、排序/收藏开关、完整筛选选项、一键设置回退、稀有确认、装备/奖励确认与退出均由 C# 编排；复用纯视觉像素计数、均色与模板匹配，没有新增 Python 产品操作。战役入口和战斗准备共用处理器，战斗保持自动化 → 退役 → 忽略低心情 → 维修的原生顺序；长期心情重启调度、强化和 GemsFarming 尚未迁移。设置超时假定正确与退役超时无条件假定成功是明确收紧的原生行为：前者失败，后者须有船确认、奖励或装备确认以及最后动作后的新帧返回；不满足就失败并留证据。`retirement.json` 保存部分尝试，选择估算不当作实测数量；离线对拍不能替代实机结果，详见路线。

战役、地图、战斗调度、导航、任务、统计、配置和设备控制均迁到 C#，完整保留上游 Config、MAP、Campaign、页面与素材规则的语义。上游方法是离线对照来源；`CampaignRun.load_campaign()` / `Campaign.run()` 不参与当前产品执行，也不作为未迁移域的兼容路径。

视觉桥只负责图像解码、模板匹配、OCR、特征/网格识别等图像计算，输入为图像与完整的识别参数，输出为观测。页面跳转选择、点击时机、等待重试、弹窗流程、地图业务状态、选敌和结算裁决均属于 C#。素材加载与服务器变体由 C# 规则层确定，桥内可以缓存图像和模型，不能据此重新调用上游业务对象。OpenCV 也可通过 C# 绑定使用；保留 Python 是现阶段复用视觉实现的选择，并非语言上的不可替代性。

新视觉接口是 `Alas.Engine.Imaging.IVision`，其常驻 worker 使用 `alas-cv/1`，只接收图像/模板字节、区域及图像处理参数。模板支持静态图片与 GIF 帧，色带检测返回投影峰值边界；选项按钮几何与行为仍在 C#。C# 持有请求与帧身份并作阈值判断；worker 不接受规则名或业务操作，不导入上游模块。Python 环境需提供 OpenCV、NumPy、ImageIO 和 SciPy 等图像计算依赖。输入错误、断流、身份漂移或超时后关闭该会话，不能消费迟到响应或切回混合宿主。当前实现范围与未完成项只在迁移路线记账。

OCR 的 `ocr_infer` 仅接收图像、裁剪区域、模型哈希和预处理/候选参数，返回分类与概率；C# 校验字母表与响应身份，执行 CTC 解码、数字修正和库存/时长解析。OCR 另需 Pillow 与 ONNX Runtime；模型目录包含固定版本的 `*.onnx` 和 `*.labels.txt`。运行时可使用单独复制的模型和图片目录，无需上游 Python 模块。

地图状态和寻路同样属于 C# 规则与引擎：`CellState` 负责 `GridInfo` 的声明/观测分离和合并，`MapPathfinder` 负责拓扑、墙、传送门、机关阻挡、伏击成本和路径节点。静态 `MapDefinition` 可以保存上游的 loop、权重、墙、传送门及机制声明；这些字段在 C# 对象构造时校验，运行时不读取 Config JSON。当前 `CampaignMapCatalog` 已将 1,370 份上游地图声明编译为 C#，包括相机视野、滑动预设和自定义格子行为；`compile_campaign_maps.py` 只在构建/同步时生成可审阅源码，`--check` 负责漂移拒绝，不是运行时转换器。上游成本场的加权前沿早停会产生自相矛盾的 predecessor，C# 采用正权最短路保持 `cost` 与连接链一致，并在对照报告中区分修正项与语义偏离。

整帧观测通过 `MapObservation` 进入该状态：C# 将视野局部坐标按相机位置映射到地图、执行编译后的忽略预测规则、在副本上预检，并在两处及以上冲突时拒绝整帧；单处冲突保留上游部分写入语义。初始化的潜艇/舰队纠正也由 C# 执行。此接口不负责从截图产生观测，视觉检测与设备接线必须另行验收。

每局 `InitializeMapData` 先重置计数和观测，再用普通声明检查清理模式覆盖，随后选择循环地图/出生表并初始化拓扑和机制。清理模式删除本局堡垒/弹跳机制，不改共享规则。累计出生表按已完成战斗次数取行，越界使用末行；缺失数允许为负，不能夹为零或当作结算。遮挡候选唯一确定时才写入推断标志，poor 模式禁止确定性预测。`MapScanner` 在 C# 中调度机位与冲突恢复，最后预测并清理舰队格；相机接口只负责有取消期限的移动和观测，不能委托 Python `full_scan`。初始化、扫描和队列超时都不构成成功结算。

`MapViewGeometry`、`MapSwipePredictor` 和 `MapCamera` 已把检测多边形到扫描观测的中间业务接入 C#：视野过滤/归一化、透视坐标和内外点击区域、原始舰队标记与海格相关度投票、滑动待确认状态、边缘定位、聚焦/居中、预设与反向边缘恢复、滑动避让区域和控制倍率。几何求解保留上游 float32 输入及消元顺序，避免恰在整数边界时落入相邻格；零格居中不消费待确认位移。`GridRecognition` 的滑动原始舰队判定独立于完整观测中的潜艇抑制，已有逐格顺序不变。运行时 Python 仅增加 `image_pair` 裁剪/缩放/灰度/相关度数值测量，不解析相机、地图或舰队；阈值和投票在 C#。

该实现通过 `MapViewSource` / `MapSwipeInput` 与识别器组合为 `IMapScanCamera`，`EngineSession.CreateMapCameraAsync` 已接截图、UI mask、具体网格检测与 ADB 手势。初始化也受超时约束，并对首次视野作边缘校正。`MapUiRecovery` 已接入会话的 `IN_MAP`/策略门控、信息条与领奖/剧情干扰、阶段入口确认、准备页和自动寻敌退出、回图及大世界弹窗顺序；初始化和刷新共用五秒/十次的几何错误确认与越界纠正。阶段入口模板、名字区域和信息条峰值由纯 CV 返回测量，规则选择、点击和等待在 C#。入口类型须由调用方按上游 Config 传入；目前只验证普通首章默认值，大世界相机工作流仍拒绝。动作或更新失败后相机实例明确失效，需重新定位。离线恢复、相机和图像对照不证明实际游戏移动或成功结算。

`GridDetector` 与 `PerspectiveDetection` 使用普通 C# 类型化配置，直接执行线段筛选、拟合、单应性校准、中心/角点/轮廓检测分支、边缘判定和格子生成；`EngineSession` 复用同一视觉进程与设备。Python 只提供图像遮罩、Hough 测量、矩阵变换/Canny、相关度位置和轮廓框，不接收地图 id，不作检测分支选择或权威状态更新。灰度素材保留原像素，原始线段保留上游 float32 运算。主地图/大世界遮罩的不同使用位置按上游语义区分；大世界局部几何可检测，格子预测与相机工作流未迁移时组合入口明确拒绝。具体对照和历史截图范围统一记录在迁移路线。

`MapArrivalCheck` 已在独立执行图中连接 C# 格子点击、新帧、原始舰队标记和地图页面信号。普通到达按连续帧计时确认；交互遮罩颜色基线在离屏聚焦后、点击前采集，战斗准备、空袭/伏击和物品弹窗由 C# 依上游优先级先识别。空袭等待已用上游红色遮罩与消失计时迁到 C#，处理后完整重定位并继续原点击；到达结果保留已处理交互顺序。传送门按上游每帧重建视图，读取中心舰队标记，确认后将相机锚到规则出口；未确认不写舰队位置。`MapMovement` 分别核对普通移动、战斗、物品谜题和候选 BOSS 探查的交互证据后更新舰队位置、格子标记与成本；候选格无战斗只记移动，胜方战斗才记战斗，返章节页仍不等于通关。物品谜题还须观测并关闭上游奖励弹窗，才增加谜题计数。弹药提示按原生信息条/颜色组合及三秒间隔被动观测，补给格经到达后二次点击和信息条等待后按上游公式记账；工件中的计算量不代表独立到账测量。同格塞壬救援和弹跳探查已接通；伏击回避/迎击已接入上述公共流程，航母谜题现接入增援等待与扫描，其他交互不能由舰队标记推断完成。可移动敌人已接入回合与重扫；战役路点在激活的迷宫格前执行原生邻格等待并重新分派。完整 `_goto` 仍须真实出击验证；当前入口只支持人工刚进入地图后的部分战役流程。

新队列的 `map_observe` 只做当前截图的局部观测；输入必须对应已迁移的 Campaign 类型，不能以完整 MAP 目录替代缺失的可执行规则和配置。返回格子/几何及原图证据，明确尚未验证全图定位和成功结算。它不导航、不进入地图，也不点击设备；首次失败留帧和调用栈，不回退旧宿主。ADB 手势的时长/位置在 C# 执行，minitouch/MaaTouch 终端仍待实现。

MAP 初始化不能仅复制最后的字段值：上游 `shape` setter 还会生成默认机位、重置权重及出生机位，`camera_sight` 的赋值先后会影响结果。构建期生成器按这些语义处理当前声明，对重复 setter、跨模块覆盖及不支持的初始化顺序明确拒绝。自定义 `grid_class` 对应普通 C# 派生类，覆写先于 `base.Merge`；公共格子与观测层不按章节名称分支。上游复制链和自定义基类纳入来源哈希，独立测试直接调用原生构造/setter/合并，不以生成器摘要自证。

逐格识别也遵循同一边界。`GridRecognition` 是 C# 的 `GridPredictor.predict` 迁移，按上游顺序组合敌人规模、敌人类型、BOSS、潜艇、舰队、谜题、当前舰队和导弹标记；`IImagePatchVision` 只返回裁剪/缩放后的模板分数、颜色相似度计数和 HSV 计数。Python worker 的 `image_patch` 操作不接受素材 id、地图名或任务调用，规则层从编译后的素材声明读取模板字节。具体检测器已经把几何结果接入 `VisibleGrid`，局部识别、全图状态更新和真实结算仍分别验收。

允许 Python 作为离线上游参考、构建期迁移辅助和测试工具，但发布后的业务路径不得依赖这些工具或导入上游 Campaign/UI/任务模块。目标是原生 C# 规则模块与 C# 引擎直接协作，不再建立携带条件、循环、方法调用和继承分派的通用 JSON 执行计划。现有 `assets.json`、Config 摘要和不完整计划仍只是离线数据，不能直接升级成运行时规则。

禁止按地图名称、编号、尺寸、服务器或页面另建坐标、阈值、路线、点击顺序、寻敌或战斗分支。动态加载、Config.when、设备协议、继承和运行时状态必须逐项验证，不能因方法短或样本通过就推断全部可静态化。结果只使用冻结的 `sortie-result/1` 合同；CampaignEnd、撤退、超时、单帧截图和影子一致都不能单独证明通关。

## 规则与引擎一起迁移

现有实验链路为 Python 规则源码 → AST 导出步骤 → JSON 计划 → C# 计划解释器。`export_upstream_data.py` 的 `derive_plan` / `campaign_method_plans` 编码条件、返回和调用，`CampaignPlanStep` 建模，`CampaignHookRunner` 再实现求值、局部变量和调用绑定。这已经包含一套 Python 子集语言的转换与解释，继续扩张会同时增加导出器、数据合同和解释器的维护负担。

推荐链路改为：上游 Python 规则与公共引擎 → 一次语义迁移 → C# 规则类直接调用 C# 公共引擎。条件、循环、局部变量、方法参数和普通覆写交给 C# 编译器；不先生成 `plan_steps`，也不让新规则通过旧解释器执行。

| 上游内容 | C# 表达与责任 |
| --- | --- |
| Config、MAP、出生表、道路及相机声明 | 类型化定义或纯数据资源；由公共加载逻辑保持覆盖顺序、格子引用和实例隔离 |
| Campaign 钩子与章节公共基类 | 普通 C# 类、方法和显式策略；公共引擎直接调用，保留原控制流及返回语义 |
| 页面图、控件、素材及服务器变体 | 完整规则定义与公共导航/交互实现；C# 确定识别参数和动作，视觉桥只返回观测 |
| 来源、版本、覆盖范围与未迁移项 | 独立迁移清单及漂移检查；缺失实现明确拒绝，不伪装为默认规则 |

例如上游 `campaign_main/campaign_3_1.py` 的 `battle_0` 包含舰队前推、救援成功则返回、否则清理谜题再调用默认战斗。这可以直接写成 C# 方法中的调用、`if` 和 `return`，无需为这些语句分别设计 JSON 编码及运行时分派。照原样迁移该文件已有的 G2 目标和 MAP 声明属于保留上游规则；在公共引擎里新增“遇到 3-1 就走特殊流程”仍属禁止的补丁。

直接迁移省掉的是中间执行格式和解释器，不会省掉业务语义实现。Python 多继承的 C3/super、`Config.when` 的选择与优先级、类级共享对象与实例状态、`None`/`False`、容器顺序及动态覆写仍须逐项映射到 C# 继承、组合或显式策略，并与原生执行独立对照。C# 的 `base` 调用不能自动代表 Python 的完整 MRO。规则与引擎须保持接口兼容，上游更新仍需源版本/哈希跟踪、差异审阅和回归；直接迁移不会自动获得后续上游改动。

迁移辅助工具若用于批量生成，应直接产出可编译、可审阅并记录来源的 C# 源码，未知语义报缺口；不以扩张通用 Python 转译器为前置任务。静态资源可以继续序列化，纯数据读取不等于解释可执行规则。

用户已要求整体舍弃旧流程：新架构在独立 `Alas.Engine` 工程中建设，不引用 `Alas.Core`，不实现旧 `IVisionEngine` 的兼容外壳，也不通过旧任务 runner、`s3_campaign_call`、计划解释器或运行时开关委托 Python。C# 规则、权威状态、视觉接口、设备、导航、任务和结果归属在新执行图中共同建设，产品组合入口整体切换。未迁移功能明确缺失，不回退旧业务。现有正确算法与冻结结果合同可在新边界内忠实重用，但不能把旧流程重新带入。

旧 Core 已从仓库删除；导出器、静态摘要和历史 oracle 仅作离线对照。Server/桌面入口现已整体切换到 Engine；不以逐模块嵌回旧架构实现迁移。`assets.json`、Config/MAP 摘要、manifest 的展示、来源追踪和完整性价值独立核对。旧失败记录和真实结算证据继续保留，不能随架构变化改记为通过。

## 当前产品组合

桌面 UI → Alas.Engine，浏览器 UI → Alas.Server → Alas.Engine。Engine 自己承载规则、状态、设备、导航与业务，不下接上游业务引擎；仅纯 CV/OCR 可调用独立 Python worker。

Server 与桌面使用 EngineControlWorkspace；配置、部署、队列与新工件报告已接线。单任务入口只接受已注册的 Engine `ITaskRunner.Kind` 并复用同一队列；按旧任务名执行、连续调度、统计、指挥喵服务和策略校验尚未迁入，明确返回不可用。Core、IVisionEngine 和旧 ALAS_ENGINE_LOOP 开关不参与产品运行；不能恢复回退以弥补未实现能力。

完整规则、业务域、发布布局及新路径真机通关仍未验收。入口切换不等于完成重写；旧成功结算不计入新 Engine。具体事实见[路线](architecture-roadmap.md)。

## 迁移顺序与最终验收

1. 在独立 C# 工程建设完整的新执行图，定义纯视觉、设备 I/O、类型化规则、出击状态和业务边界；不引用旧 Core，也不新增 legacy 兼容实现。此顺序用于组织新架构内部工作，不是逐模块替换旧产品。
2. 将规则文件和公共基类一起迁成 C#：静态声明使用类型化配置/资源，钩子使用普通方法，明确映射服务器变体、配置覆盖、继承调用顺序和签名。用迁移清单记录源版本及未知语义，构建期辅助可直接生成 C#，不再扩张运行时 JSON 控制流解释器。
3. 在新执行图内接通 C# 设备层、权威状态和纯视觉观测，忠实迁移页面/控件/弹窗及地图移动、进战、结算流程。复用整套上游规则，不按地图或页面补丁推进。
4. 补全 C# 战役加载、钩子执行和战斗调度，使选敌/寻路/循环进入真实产品路径，关闭业务 Python 后仍能完成出击、成功结算及返回章节页。现有 34 个注册原语与静态调用编码不能代替此验收。
5. 依照通用任务模型迁移全部周期任务、工具、大世界、调度、配置与统计。逐域给出产品输入、可观测效果、错误与取消证据；不以“已注册任务”计完成。
6. 桌面与 Server 的产品组合入口整体切换到新执行图，旧流程从产品依赖和发布包移除。发布包只保留视觉 Python 及其依赖；对非视觉 Python 操作设拒绝边界并审计运行轨迹。不提供旧业务回退；离线原生对照独立运行。

完成判据同时包含：所有域的执行归属表、无业务 Python 依赖的发布验证、纯视觉协议负向检查、完整规则与控制流对照、真实产品路径/成功结算、失败工件及性能基线。必须能够禁用全部业务 Python 模块后运行产品验收，不能以删除脚本、静态扫描、方法数量或离线绿灯替代。

## 独立任务入口

`Alas.Engine.Cli run --queue <文件>` 使用新引擎的任务模型，公共参数见 `--help`。JSON 数组只描述任务 id、kind、input、required、dependsOn 和 timeoutSeconds，不编码条件、循环、调用步骤或规则继承；业务控制流在已编译 runner 中。输入由 runner 校验，未知任务和字段明确拒绝。示例队列：

```json
[
  { "id": "inspect", "kind": "observe" },
  { "id": "key", "kind": "data_key", "input": { "forceCollect": false }, "dependsOn": ["inspect"] }
]
```

`--dry-run` 不创建设备/视觉会话；动作任务实际执行需 `--allow-actions` 和明确的 `--package`。OCR 模型通过 `--models` 配置，例如本地上游快照中的 `bin/ocr_models`。每个任务含未跑/失败都有单独工件；失败保存堆栈及已捕获帧。`--continue-on-failure` 显式允许独立任务继续，不能绕过依赖。`--resume <批次目录>` 必须沿用同一队列与会话配置，只跳过有完整成功工件的任务，失败或未跑项重新执行。恢复校验和用于发现工件损坏或变更，不是对可同时重写文件与哈希者的身份认证。

当前导航及资料密钥任务支持取消和期限到期，不把超时当成任务完成。后续战役任务须独立保留关卡边界取消与冻结结果合同；不能把通用任务成功、页面到达或库存读取当作战役通关。

现有架构守卫中“必须调用原生调度器”“不保留 C# 导航类”等检查只是 legacy 路径的过渡保护；新 Engine 验收须使用原生语义与新执行归属的行为证据，不能永久阻止 C# 实现，也不能简单删除检查来掩盖功能丢失。

## 现有离线导出契约

以下约束保护仍在使用的导出消费者，不要求把计划格式补成完整语言后才能开始 C# 规则迁移。导出步骤的覆盖率与 C# 规则迁移覆盖率分开记录。

导出器使用静态 AST 和通用符号解析。方法步骤、分支、终止、父类委托、参数声明顺序、必选参数、默认 `None`、仅位置参数和仅关键字参数都必须保留；无法表达的真实语句生成 `plan_complete=false` 和原因，不能删除后宣称完整。`campaign.initial_state` 只包含源类自身已解析的标量初态，范围标为 `declared`，不代表完整继承或运行时状态。

页面图、Campaign 声明、Config、MAP、素材和 manifest 由源码重建并做完整性校验。上游缺失入口素材符号仍是失败，ImportError、`cannot import` 或静态摘要不能豁免缺失、篡改和未解析项。完整快照检查目前保留三个既有 ENTRANCE 源缺失失败；不能把它们归类为成功，也不能增加逐地图替代规则。

## 旧实验执行器与宿主语义（仅离线对照）

以下是现有解释器的验证边界。迁入 C# 规则的行为仍须保持这些已核对的上游语义；新规则不依赖解释器，现有缺口也不能因更换架构而改记为通过。

执行器区分分支自然落空与显式返回，保留 `None`、`False`、`and/or` 操作数和局部变量真实类型。tuple 与 list 分开编码；父类委托虽然保留方法名与参数，但尚缺词法定义类和完整 MRO，执行器与宿主翻译明确拒绝，不能以同名原语替代。`CampaignEnd` 与 `MapEnemyMoved` 按类型化控制流处理；错误消息子串不能代替异常类型。

舰队前缀按上游 Fleet 属性条件解析为当前实例，未配置二队及同队调用不触发切队；调用优先分派到已导出的实例覆写，包括不完整覆写的明确拒绝。静态调用审计也按同一绑定顺序分类；仅四个返回 `self` 的舰队属性具有此含义，不能把任意点号路径当成实例方法。

真机渠道拒绝 error、refused、缺失 value 和未确认写入。只读状态使用受限白名单；危险路径在解析中间属性前也需要动作授权。设备状态缺失或类型错误直接失败，不以零、默认舰队或旧快照继续决策。原生动作后重新读取地图；格子标志、弹药和其他已迁移写入先获上游确认，再更新本地模型。`fleet_ensure`、`clear_chosen_enemy` 的布尔结果透传；`goto`、`switch_to` 等原生 `None` 不能变成成功布尔值。撤退只有观察到原生 CampaignEnd 才设置结束状态。

组合方法的返回值逐方法遵循上游控制流：`clear_enemy`、`clear_any_enemy`、`clear_siren`、三个清路障方法与 `clear_filter_enemy` 在选到目标并正常调用末端动作后返回 `True`，不能透传末端的 `False` 而额外执行兜底。无目标仍返回 `False`；错误、拒绝及控制流信号不转换为真。`verify_r5_clear_returns.py` 以原生 Map、CampaignBase 和 RoadGrids 核对 312 个返回/动作/短路场景，另验渠道空结果拒绝；这些布尔值不表示成功结算。

原语循环不能按录制/设备宿主类型缩短。`fleet_2_protect` 保留原生 20 轮，每次从当前地图重新选择；`clear_all_mystery` 仅在没有可选目标后返回假。实验执行器仍有 100 次清理动作预算，但耗尽且仍有目标时明确阻塞，不能继续调用后续钩子。录制宿主未提供地图反馈时也受此约束。`verify_r5_primitive_loops.py` 对照 15 个原生状态演进场景，另验 3 个预算拒绝场景；预算是实验执行限制，不是上游结束条件。

## 旧运行影子观测（已退役）

原生 `Campaign.run()` 作用域安装临时日志处理器，只记录拥有本次调用的线程和明确的 BATTLE、`Using function:`、结束及无战斗信号，并从本次实例配置读取变体。结果通过 `shadow_observation` 返回；不按修改时间寻找共享日日志，也不读取其他出击的内容。每次尝试使用唯一影子工件；缺证据、格式错误、写入失败、空观测或跳过观测均告警且不算一致，同时保留原始出击结论和批次索引。dry-run 不生成影子结论。

影子比对只证明已观测轮次的钩子选择，不证明格子目标、动作效果、相机、路线、结算或 C# 替换路径。`verify_r5_observation.py` 覆盖当前运行隔离、重复尝试、被锁旧日志、缺证据和观测故障；`verify_r5_host_contract.py` 覆盖渠道错误、状态回写、类型化控制流和地图标志。

## 验收分层

| 检查 | 能证明 | 不能证明 |
| --- | --- | --- |
| 源码重建与导出校验 | 当前快照声明、步骤、类型、来源未丢失或被篡改 | 动态调用、继承完整性或实战成功 |
| Python 反例与 C# 对拍 | 指定输入、状态和控制流的语义 | 未覆盖表达式、运行时状态和设备效果 |
| 原语、选择、寻路、循环扫描 | 指定夹具的结果和动作记录 | 全部局面、性能和真实动作效果 |
| 递归调用翻译 | 结构步骤、参数形状和运行期引用被分类 | 上游方法存在、可调用或实战成功 |
| `invoked_ops` 覆盖 | 夹具运行确实进入的原语 | 静态注册、日志文字或相邻原语 |
| 原生真机结算 | 对应本次原生出击的合同结果 | C# 替换路径或其他章节 |

各检查必须分别报告完整、阻塞、结构步骤、静态编码、运行期解析、跳过、失败和成功结算；不把未执行、导入失败、超时或空样本计入通过。主要入口包括 `verify_plan_export.py`、`verify_pages_export.py`、`verify_export_integrity.py`、`verify_r5_execution_semantics.py`、`verify_r5_host_contract.py`、`verify_r5_observation.py`、`verify_r5_calls.py` 和 `verify_r5_coverage.py`。整体回归使用 `python tools/diagnostics/verify_all.py --docs-only`，并追加架构、隐私和结果合同检查。
