# 上游引擎重写：目标、边界与验证

最终目标是 C# 执行全部非视觉逻辑，Python 只保留确有必要的 CV/OCR 桥接。当前产品仍是 C# 外层编排加 Python 游戏执行，不能称为重写完成。迁移已是明确目标，不再以“是否值得替换”的评估作为终点；现有正确性与真实路径门槛用于验证替换，不用于永久维持 Python 业务。当前阶段和缺口以[迁移路线](architecture-roadmap.md)为准。

## 目标与边界

战役、地图、战斗调度、导航、任务、统计、配置和设备控制均迁到 C#，完整保留上游 Config、MAP、Campaign、页面与素材规则的语义。上游方法是对照来源，不是必须保留的运行时。当前 `CampaignRun.load_campaign()` / `Campaign.run()` 仅是尚未替换域的兼容路径。

视觉桥只负责图像解码、模板匹配、OCR、特征/网格识别等图像计算，输入为图像与完整的识别参数，输出为观测。页面跳转选择、点击时机、等待重试、弹窗流程、地图业务状态、选敌和结算裁决均属于 C#。素材加载与服务器变体由 C# 规则层确定，桥内可以缓存图像和模型，不能据此重新调用上游业务对象。OpenCV 也可通过 C# 绑定使用；保留 Python 是现阶段复用视觉实现的选择，并非语言上的不可替代性。

新视觉接口是 `Alas.Engine.Imaging.IVision`，其常驻 worker 使用 `alas-cv/1`，只接收图像/模板字节、区域及图像处理参数。模板支持静态图片与 GIF 帧，色带检测返回投影峰值边界；选项按钮几何与行为仍在 C#。C# 持有请求与帧身份并作阈值判断；worker 不接受规则名或业务操作，不导入上游模块。Python 环境需提供 OpenCV、NumPy、ImageIO 和 SciPy 等图像计算依赖。输入错误、断流、身份漂移或超时后关闭该会话，不能消费迟到响应或切回混合宿主。当前实现范围与未完成项只在迁移路线记账。

允许 Python 作为离线上游参考、构建期迁移辅助和测试工具，但发布后的业务路径不得依赖这些工具或导入上游 Campaign/UI/任务模块。目标是原生 C# 规则模块与 C# 引擎直接协作，不再建立携带条件、循环、方法调用和继承分派的通用 JSON 执行计划。现有 `assets.json`、Config 摘要和不完整计划仍只是离线数据，不能直接升级成运行时规则。

禁止按地图名称、编号、尺寸、服务器或页面另建坐标、阈值、路线、点击顺序、寻敌或战斗分支。动态加载、Config.when、设备协议、继承和运行时状态必须逐项验证，不能因方法短或样本通过就推断全部可静态化。结果只使用冻结的 `sortie-result/1` 合同；CampaignEnd、撤退、超时、单帧截图和影子一致都不能单独证明通关。

## 规则与引擎一起迁移

现有实验链路为 Python 规则源码 → AST 导出步骤 → JSON 计划 → C# 计划解释器。`export_upstream_data.py` 的 `derive_plan` / `campaign_method_plans` 编码条件、返回和调用，`CampaignPlanStep` 建模，`CampaignHookRunner` 再实现求值、局部变量和调用绑定。这已经包含一套 Python 子集语言的转换与解释，继续扩张会同时增加导出器、数据合同和解释器的维护负担。

推荐链路改为：上游 Python 规则与公共引擎 → 一次语义迁移 → C# 规则类直接调用 C# 公共引擎。条件、循环、局部变量、方法参数和普通覆写交给 C# 编译器；不先生成 `plan_steps`，也不让新规则通过旧解释器执行。

| 上游内容 | C# 表达与责任 |
| --- | --- |
| Config、MAP、出生表、道路及相机声明 | 类型化定义或纯数据资源；由公共加载逻辑保持覆盖顺序、格子引用和实例隔离 |
| Campaign 钩子与章节公共基类 | 普通 C# 类、方法和显式策略；公共引擎直接调用，保留原控制流及返回语义 |
| 页面图、控件、素材及服务器变体 | 完整规则定义与公共导航/交互实现；C# 确定识别参数和动作，视觉桥只返回观测 |
| 来源、版本、覆盖范围与未迁移项 | 独立迁移清单及漂移检查；缺失实现明确拒绝，不伪装为默认规则 |

例如上游 `campaign_main/campaign_3_1.py` 的 `battle_0` 包含舰队前推、救援成功则返回、否则清理谜题再调用默认战斗。这可以直接写成 C# 方法中的调用、`if` 和 `return`，无需为这些语句分别设计 JSON 编码及运行时分派。照原样迁移该文件已有的 G2 目标和 MAP 声明属于保留上游规则；在公共引擎里新增“遇到 3-1 就走特殊流程”仍属禁止的补丁。

直接迁移省掉的是中间执行格式和解释器，不会省掉业务语义实现。Python 多继承的 C3/super、`Config.when` 的选择与优先级、类级共享对象与实例状态、`None`/`False`、容器顺序及动态覆写仍须逐项映射到 C# 继承、组合或显式策略，并与原生执行独立对照。C# 的 `base` 调用不能自动代表 Python 的完整 MRO。规则与引擎须保持接口兼容，上游更新仍需源版本/哈希跟踪、差异审阅和回归；直接迁移不会自动获得后续上游改动。

迁移辅助工具若用于批量生成，应直接产出可编译、可审阅并记录来源的 C# 源码，未知语义报缺口；不以扩张通用 Python 转译器为前置任务。静态资源可以继续序列化，纯数据读取不等于解释可执行规则。

用户已要求整体舍弃旧流程：新架构在独立 `Alas.Engine` 工程中建设，不引用 `Alas.Core`，不实现旧 `IVisionEngine` 的兼容外壳，也不通过旧任务 runner、`s3_campaign_call`、计划解释器或运行时开关委托 Python。C# 规则、权威状态、视觉接口、设备、导航、任务和结果归属在新执行图中共同建设，产品组合入口整体切换。未迁移功能明确缺失，不回退旧业务。现有正确算法与冻结结果合同可在新边界内忠实重用，但不能把旧流程重新带入。

旧产品、导出器和解释器当前仍在仓库，不能把新增独立工程说成已删除旧执行路径。它们作为现状与离线对照保留，完整产品切换后从发布和产品依赖图中移除；不以逐模块嵌回旧架构实现迁移。`assets.json`、Config/MAP 摘要、manifest 的展示、来源追踪和完整性价值独立核对。旧失败记录和真实结算证据继续保留，不能随架构变化改记为通过。

## 实际执行归属复核

以 `7302594` 为复核基线，本项目已跟踪 216 个 Python 文件，其中 185 个在 `tools/diagnostics/`；其余 31 个混合了宿主、导出、同步与运行支撑。这个数量不包含上游快照，不能换算迁移完成率。最近的 Python 调整主要是对照工具，但当前生产调用也确实仍包含大量 Python 业务。

| 能力 | 当前权威执行路径 | 目标 |
| --- | --- | --- |
| 会话、外层队列、工件、API/UI | `AlasSession`、`TaskQueue`、Core Runtime | 保留并接通 C# 业务执行 |
| 战役与钩子 | `CampaignBatchRunner.Run` → `IVisionEngine.RunCampaignPlan` → `s3_run_plan` → 原生 `Campaign.run()` | C# 配置/规则加载、继承分派与完整出击状态机 |
| 地图、选敌、寻路 | 已有 C# 实现，但生产状态来自 Python；主要用于离线实验 | C# 持有权威地图状态、成本场、舰队和动作反馈 |
| 游戏导航与弹窗 | `NavigateTask` → `ui_ensure`；C# `PageGraph` 只有图算法 | C# 消费完整页面图、控件规则与视觉观测 |
| 周期任务与大世界动作 | `PeriodicRunTask` / `OsActionTask` → `periodic_run` → 原生任务 | C# 任务 runner 与域内状态机 |
| 连续调度与工具 | `SchedulerRunTask` / `ToolRunTask` → `scheduler_run` / `tool_run` | C# 调度、持久状态、取消和错误恢复 |
| 配置、统计与策略 | 宿主 `config_get`、统计接口、`shop_strategy_validate` 等仍调用 Python | C# 存储/查询与类型化策略；业务策略迁成 C# 实现，不能运行时 exec Python |
| 设备 I/O | C# 有 `AdbTransport` / `DeviceController`，主要由诊断使用；产品会话仍配置 Python 设备后端 | C# 统一设备接口，逐后端迁移并验收 |
| CV/OCR | Python 视觉宿主 | 收窄为纯识别服务，可保留现有算法和模型 |

`tools/alas_vision.py` 的 OPS 当前有 58 个协议入口，包括完整任务、导航、统计和设备操作；`IVisionEngine` 实际是混合业务宿主接口。入口数量不代表工作量，尤其 `s3_campaign_call` 可继续进入任意受限的原生业务方法。将 C# 原语改为调用此接口，只是转发，不能算完成引擎迁移。

## 迁移顺序与最终验收

1. 在独立 C# 工程建设完整的新执行图，定义纯视觉、设备 I/O、类型化规则、出击状态和业务边界；不引用旧 Core，也不新增 legacy 兼容实现。此顺序用于组织新架构内部工作，不是逐模块替换旧产品。
2. 将规则文件和公共基类一起迁成 C#：静态声明使用类型化配置/资源，钩子使用普通方法，明确映射服务器变体、配置覆盖、继承调用顺序和签名。用迁移清单记录源版本及未知语义，构建期辅助可直接生成 C#，不再扩张运行时 JSON 控制流解释器。
3. 在新执行图内接通 C# 设备层、权威状态和纯视觉观测，忠实迁移页面/控件/弹窗及地图移动、进战、结算流程。复用整套上游规则，不按地图或页面补丁推进。
4. 补全 C# 战役加载、钩子执行和战斗调度，使选敌/寻路/循环进入真实产品路径，关闭业务 Python 后仍能完成出击、成功结算及返回章节页。现有 34 个注册原语与静态调用编码不能代替此验收。
5. 依照通用任务模型迁移全部周期任务、工具、大世界、调度、配置与统计。逐域给出产品输入、可观测效果、错误与取消证据；不以“已注册任务”计完成。
6. 桌面与 Server 的产品组合入口整体切换到新执行图，旧流程从产品依赖和发布包移除。发布包只保留视觉 Python 及其依赖；对非视觉 Python 操作设拒绝边界并审计运行轨迹。不提供旧业务回退；离线原生对照独立运行。

完成判据同时包含：所有域的执行归属表、无业务 Python 依赖的发布验证、纯视觉协议负向检查、完整规则与控制流对照、真实产品路径/成功结算、失败工件及性能基线。必须能够禁用全部业务 Python 模块后运行产品验收，不能以删除脚本、静态扫描、方法数量或离线绿灯替代。

现有架构守卫中“必须调用原生调度器”“不保留 C# 导航类”等检查只是 legacy 路径的过渡保护；迁移对应域时须用原生语义与新执行归属的行为验收替换，不能永久阻止 C# 实现，也不能简单删除检查来掩盖功能丢失。

## 现有离线导出契约

以下约束保护仍在使用的导出消费者，不要求把计划格式补成完整语言后才能开始 C# 规则迁移。导出步骤的覆盖率与 C# 规则迁移覆盖率分开记录。

导出器使用静态 AST 和通用符号解析。方法步骤、分支、终止、父类委托、参数声明顺序、必选参数、默认 `None`、仅位置参数和仅关键字参数都必须保留；无法表达的真实语句生成 `plan_complete=false` 和原因，不能删除后宣称完整。`campaign.initial_state` 只包含源类自身已解析的标量初态，范围标为 `declared`，不代表完整继承或运行时状态。

页面图、Campaign 声明、Config、MAP、素材和 manifest 由源码重建并做完整性校验。上游缺失入口素材符号仍是失败，ImportError、`cannot import` 或静态摘要不能豁免缺失、篡改和未解析项。完整快照检查目前保留三个既有 ENTRANCE 源缺失失败；不能把它们归类为成功，也不能增加逐地图替代规则。

## 现有实验执行器与宿主语义

以下是现有解释器的验证边界。迁入 C# 规则的行为仍须保持这些已核对的上游语义；新规则不依赖解释器，现有缺口也不能因更换架构而改记为通过。

执行器区分分支自然落空与显式返回，保留 `None`、`False`、`and/or` 操作数和局部变量真实类型。tuple 与 list 分开编码；父类委托虽然保留方法名与参数，但尚缺词法定义类和完整 MRO，执行器与宿主翻译明确拒绝，不能以同名原语替代。`CampaignEnd` 与 `MapEnemyMoved` 按类型化控制流处理；错误消息子串不能代替异常类型。

舰队前缀按上游 Fleet 属性条件解析为当前实例，未配置二队及同队调用不触发切队；调用优先分派到已导出的实例覆写，包括不完整覆写的明确拒绝。静态调用审计也按同一绑定顺序分类；仅四个返回 `self` 的舰队属性具有此含义，不能把任意点号路径当成实例方法。

真机渠道拒绝 error、refused、缺失 value 和未确认写入。只读状态使用受限白名单；危险路径在解析中间属性前也需要动作授权。设备状态缺失或类型错误直接失败，不以零、默认舰队或旧快照继续决策。原生动作后重新读取地图；格子标志、弹药和其他已迁移写入先获上游确认，再更新本地模型。`fleet_ensure`、`clear_chosen_enemy` 的布尔结果透传；`goto`、`switch_to` 等原生 `None` 不能变成成功布尔值。撤退只有观察到原生 CampaignEnd 才设置结束状态。

组合方法的返回值逐方法遵循上游控制流：`clear_enemy`、`clear_any_enemy`、`clear_siren`、三个清路障方法与 `clear_filter_enemy` 在选到目标并正常调用末端动作后返回 `True`，不能透传末端的 `False` 而额外执行兜底。无目标仍返回 `False`；错误、拒绝及控制流信号不转换为真。`verify_r5_clear_returns.py` 以原生 Map、CampaignBase 和 RoadGrids 核对 312 个返回/动作/短路场景，另验渠道空结果拒绝；这些布尔值不表示成功结算。

原语循环不能按录制/设备宿主类型缩短。`fleet_2_protect` 保留原生 20 轮，每次从当前地图重新选择；`clear_all_mystery` 仅在没有可选目标后返回假。实验执行器仍有 100 次清理动作预算，但耗尽且仍有目标时明确阻塞，不能继续调用后续钩子。录制宿主未提供地图反馈时也受此约束。`verify_r5_primitive_loops.py` 对照 15 个原生状态演进场景，另验 3 个预算拒绝场景；预算是实验执行限制，不是上游结束条件。

## 当前运行影子观测

原生 `Campaign.run()` 作用域安装临时日志处理器，只记录拥有本次调用的线程和明确的 BATTLE、`Using function:`、结束及无战斗信号，并从本次实例配置读取变体。结果通过 `shadow_observation` 返回；不按修改时间寻找共享日日志，也不读取其他出击的内容。每次尝试使用唯一影子工件；缺证据、格式错误、写入失败、空观测或跳过观测均告警且不算一致，同时保留原始出击结论和批次索引。dry-run 不生成影子结论。

影子比对只证明已观测轮次的钩子选择，不证明格子目标、动作效果、相机、路线、结算或 C# 替换路径。`verify_r5_observation.py` 覆盖当前运行隔离、重复尝试、被锁旧日志、缺证据和观测故障；`verify_r5_host_contract.py` 覆盖渠道错误、状态回写、类型化控制流和地图标志。

## 验收分层

| 检查 | 能证明 | 不能证明 |
| --- | --- | --- |
| 源码重建与导出校验 | 当前快照声明、步骤、类型、来源未丢失或被篡改 | 动态调用、继承完整性或实战成功 |
| Python 反例与 C# 对拍 | 指定输入、状态和控制流的语义 | 未覆盖表达式、运行时状态和设备效果 |
| 原语、选择、寻路、循环扫描 | 指定夹具的结果和动作记录 | 全部局面、性能和真实动作效果 |
| 递归调用翻译 | 结构步骤、参数形状和运行期引用被分类 | 上游方法存在、可调用或实战成功 |
| `invoked_ops` 覆盖 | 夹具运行确实进入的原语 | 静态注册、日志文字或相邻原语 |
| 原生真机结算 | 对应本次原生出击的合同结果 | C# 替换路径或其他章节 |

各检查必须分别报告完整、阻塞、结构步骤、静态编码、运行期解析、跳过、失败和成功结算；不把未执行、导入失败、超时或空样本计入通过。主要入口包括 `verify_plan_export.py`、`verify_pages_export.py`、`verify_export_integrity.py`、`verify_r5_execution_semantics.py`、`verify_r5_host_contract.py`、`verify_r5_observation.py`、`verify_r5_calls.py` 和 `verify_r5_coverage.py`。整体回归使用 `python tools/diagnostics/verify_all.py --docs-only`，并追加架构、隐私和结果合同检查。
