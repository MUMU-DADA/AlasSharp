## 本轮修复

- 周期任务原先只看输入中的授权字段，队列 JSON 可能绕过会话的 dry-run。现先检查
  会话授权；未满足时记前置跳过，required 任务才失败。宿主原有输入闸门继续保留。
- 周期任务执行原先从 AST 猜第一个类并统一调用 `run()`，会丢失任务绑定、`opsi_*` 方法、
  活动参数和 `TaskEnd` 语义。现从上游 `args.json` 解析 Scheduler.Command，绑定对应配置并
  调用 `AzurLaneAutoScript.run()`；一次性覆盖走上游 `config.override()`，设备配置在调用后恢复。
- 导航任务补充会话动作授权和设备配置检查。只读设备会话可截图，但不能升级为导航或周期动作。
- 导航与观测分别接入 `NavigateTask` / `ObserveTask`，删除旧 CLI 编排；多回合、设备错误、
  失败即停和 tick 边界取消均留在核心任务。`run` 与 `goto` 已退化为迁移提示，不能再建立
  自己的任务入口。
- 队列文件解析、runner 注册、断点与停止文件监视已收敛到 `Runtime/QueueExecution`；
  CLI 的 `queue` 分支仅传公共参数和排版结果。页面、控件及关卡进度诊断脚本的导航调用也
  统一生成临时 `navigate` 队列，并为新证据标记入口来源。
- 队列文件原先会把 `input: []` 静默转成缺省输入，离线活动清点因此实际执行并落盘工件。
  现在通用解析器在启动会话前拒绝非对象 `input`，错误路径回归覆盖这一反例。
- 断点原先只按任务 id 跳过：同 id 改 `input` 后，第二次 `--resume` 仍直接跳过新任务，
  退出码为 0。现在完成项保存请求及会话运行参数，只有身份一致才续用；dry-run 完成项
  不会跳过后来的真实运行，旧 id-only 断点保守重跑。同请求的累积语义保持不变。
- 显式 `--resume-state` 原先只用参数的目录，再固定读取 `state.json`，自定义文件名被忽略；
  现在直接读取指定文件。显式文件不存在时原先仍启动会话并从头运行，现改为在会话前报输入错误。
  CLI 回归覆盖复制改名与不存在两条路径。
- 损坏的断点原先会被当成空完成集，静默重跑已有任务；现在已找到的断点必须可解析且包含
  `completed` 对象，否则会话启动前报输入错误。完成项还会核对结论词与任务身份，避免
  `failed` 被误当成已完成而跳过。CLI 回归覆盖坏 JSON 和篡改结论的断点。
- 抓帧失败后不再识别旧帧；页面错误、异常栈、输入校验与取消均留有证据。
- 任务内部取消后，即使已经是队列最后一个任务，也记 `cancelled`，不误报 `partial`。
- 域的前置校验抛异常时，队列仍写失败工件、跳过后续任务并保留原因，避免校验异常让证据链中断。
- 运行时自检使用每次唯一的 workspace，工件核对完成后才清理，避免并发验证互删工件。
- 结果审计补充通用结构化工件输入，交叉核对合同、单关、索引与会话日志；没有修改生产结果词表、
  上游加载、章节配置、原生战役调度或地图规则。

## 后续复核

- 周期任务的 `allow_actions` 曾用 Python 真值转换，字符串 `"false"` 会通过放行判定。
  宿主现在只接受 JSON 布尔值 `true`，C# 前置条件也拒绝错误类型；拒绝路径验证了零构造。
- 队列 `input` 的非对象值不再静默变成缺省输入。`--resume` 现在按任务内容和会话运行参数
  匹配已完成项，并绑定有序前序任务；同 id 改输入、改变前序任务、重排队列、从 dry-run
  切到真跑或读取旧格式断点时会重新执行。只在队尾追加任务仍可续跑已有完成项；这些路径
  均由真实 CLI 的离线回归覆盖。
- 身份匹配的断点若把 `outcome` 写成失败或未知值，现在会在会话启动前拒绝，不能伪装成
  已完成任务。战役队列输入也逐项校验章节、布尔开关、时间、整数轮次与舰队数；错误类型、
  小数轮次、越界值和未知字段记前置跳过，不会静默回退到可能扩大出击范围的默认值。
- `os_state` 复用上游 `globe_detect` 只读路径，保存单应性、坐标与日志；离线 map/globe
  两类帧和错误输入均已对拍，不能据此声称大世界动作流程已完成。
- 静态报告可展开完整任务证据和前置条件，原始 JSON 不再截断；生成单次运行视图时
  不改动工件目录。配置、队列和运行控制的统一前端仍未交付。
- 报告现在把结构错误的工件和日志行标为 `unreadable_artifact`，保持结构化报告可生成，
  不会因合法 JSON 的字段类型不符直接退出；七种错误形状已有反例回归。
- 报告读取合法 JSON 但顶层或嵌套字段类型错误的队列、批次、任务、单关工件和日志行时，
  现在保留结构化 `unreadable_artifact` finding 和不完整证据标记，不再直接抛异常让报告缺失。
- 真机冒烟清单已删除“周期入口未实现”“本局撤退未取证”的旧结论，新增独立的
  `--read-only-device` 路径。新队列入口已现场完成只读观测、往返导航、1-1 成功结算及原生
  `reward` 样本；`device_smoke.py` 增加退出码、报告与工件交叉核对，不能把缺证据误报为成功。

## Python.NET 评估

当前产品已有进程内 CPython 宿主：`PythonHost` 通过 P/Invoke 调用 CPython C API，
`IVisionEngine` 只消费 `alas_vision.handle_line(str) -> str`。另有调用同一入口的进程外 worker。
项目没有引用 `Python.Runtime`。因此改用 Python.NET 是替换嵌入层，不是把跨进程调用改成进程内。

既有基线中，Python 侧直接调用 `handle_line` 的稳态往返约 10 微秒/次，
C# 进程内 `ping` 往返约 21 微秒/次；真实抓帧约 346 毫秒/帧，主要耗时不在语言互操作。
Python.NET 可减少部分原生句柄和 GIL 封装代码，但仍需管理解释器版本、初始化、对象生命周期、
线程与异常；它本身不会改变上游地图、视觉或任务调度语义。当前不迁移。
若后续有维护性或兼容性故障，再在 `IVisionEngine` 后增加可切换实现，用同一协议对拍
冷启动、稳态调用、内存、异常恢复和真实产品路径，并保留现有宿主回退。

按用户授权，历史已重写并推送：453 个提交、5733 个唯一 blob 的复扫中，个人主目录、
个人 fork 来源标识、明确凭据和 `runs/` 历史路径均为 0；远端 `master` 与清理后提交一致。
Git 作者/提交者身份与时间戳按用户要求保留。重写前 bundle 与未提交功能补丁只保存在本地
忽略目录 `data/privacy-history/`，没有进入仓库。
