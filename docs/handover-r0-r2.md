## 八、page_guild 结案：入口可见但不可用（账号门禁）

`alashub goto page_guild` 的真机 hop 日志：

```
[hop 2] on=page_main click ui_white/MAIN_GOTO_GUILD_WHITE score=0.9487 at (1188,680) ->   (空)
[hop 0] on=      click <BACK 自救> score=0.0000
```

导航器**正确找到并点击**了入口（模板分 0.9487），但点击后的画面**判定不出任何页面**，
于是它按「未到达」走 BACK 自救 → 回主界面重试 → 循环到失败。

为定位，我按**同一坐标**再点一次并抓帧（`data/_guild_screen.png`）：4 秒后画面**仍是主界面**，
与点击前一致 —— 即这次点击**没有任何可见效果**。合理解释是：入口渲染在屏上但对点击无响应
（典型的等级/进度门禁按钮），而不是「点到了别处」或「导航选错边」。

**据此更正第 51 轮的判断**：当时由「入口在屏」推出「是导航侧问题」，现在证据显示入口
**可见但不可用** —— `page_guild` 的不可达仍属**账号状态门禁**（该号 Lv.32、只解锁第 1 章）。
于是 29/34 可以用账号状态解释完，**不需要引入代码回归的假设**。

**未做决定性验证（如实标注）**：「渲染但无视点击」是**推断**。决定性实验是拿一个已知可用按钮
在同一区域做对照（点击后画面必须改变），以及确认大舰队的解锁条件 —— 两条都未做。

### 八之补充二：`page_event_list` 是**可达**的 —— 失败在入口判据，不是账号门禁

先回到主界面并**核对了状态**（上一轮我漏了这步，导致一次无效探针：当时还在商店页，白点了一下）：

**结论**：活动入口**在屏、可点、且确实通往 `page_event_list`** —— 这个页在这台账号上**是可达的**。
所以它的 goto 失败属于**入口判据侧**：上游页面图给出的边是
`ui_white/MAIN_GOTO_EVENT_LIST_WHITE`，而该卡片是**带美术图的缩略图**，
颜色比对（实测 17.07，阈值 10）落在外侧，导航因此找不到这条边。

**与 `page_guild` 恰好相反**：那一个是"入口渲染但对点击无响应"（账号门禁），
这一个是"入口能点通但判据认不出"（判据问题）。**同一份失败列表里混着两类根因**，
不能用一个解释覆盖 —— 这也是我先前两次推断都被推翻的原因。

**下一轮的具体动作**（已定位到足够细）：看上游对这条边用的是颜色还是模板
（`variants` 里是否有别的资产）、以及本客户端白皮界面该用哪一个；
若确实是"用颜色判美术缩略图"，正确的做法是换判据口径，而不是照搬 `IN_MAP` 的阈值垫片。

### 八之补充三：`page_event_list` 入口的**判据本质不稳定**（读上游素材定义得到）

上游 `module/ui_white/assets.py`：

```python
MAIN_GOTO_EVENT_LIST_WHITE = Button(
    area={'cn': (1181, 83, 1260, 160)},       # 79x77，右上角
    color={'cn': (147, 155, 186)},
    file={'cn': './assets/cn/ui_white/MAIN_GOTO_EVENT_LIST_WHITE.png'})   # 模板也有
```

对照现场事实：

| 事实 | 值 |
| --- | --- |
| 该素材的区域 | (1181, 83, 1260, 160) |
| 我实测的相似度 | **17.07**（阈值 10）→ 颜色判据不命中 |
| 我成功点通的坐标 | (1222, 150) —— **正落在这个区域内** |

## 九、R4 第一屏与三处根因修复（第 101–116 轮）

### 做出来的

| 东西 | 说明 | 入口 |
| --- | --- | --- |
| 运行报告的**单文件 HTML 视图** | 结论卡片/任务表（含边界快照）/关卡表/发现/日志 scope；自带样式、无外部引用 | `python tools\report_html.py <artifacts>\<时间戳>` |

### 修掉的三处根因（都不是"加功能"，是"把约定落成代码"）

1. **"什么算一次运行"只有一处判定**（`RunReport.IsRunDirectory`）：此前 `report` / `runs` / `--resume`
   各自扫目录，混进来的目录会被当成一次运行 —— 表现为误导性发现（`log_missing`）、
   列表多一条、以及**断点读到别的运行**（静默跳过没跑过的任务）。
2. **断点文件改成累积语义**：`state.json` 以前每次重写、只记本次完成的任务，于是一次"全都跳过"的运行
   会**清空**历史，下一次 `--resume` 就把已完成的任务**重新执行** —— 对战役域就是**再花一次石油**。
3. **派生数据不写进运行目录**：生成的视图写在 `<artifacts>-views\`；运行目录里的文件数是
   "工件数"的一部分，往里塞页面等于篡改证据（实测过工件数 3→4）。
