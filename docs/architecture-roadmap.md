# 迁移路线与当前状态

最终目标：C# 执行全部非视觉逻辑，Python 仅保留必要的 CV/OCR 桥接。产品入口已切换到独立 Engine，完整业务重写尚未完成。
R0 证据、R1 运行时、R2 任务模型与 R4 UI 为现有基础；主线转为拆除产品路径的业务 Python 依赖、完成 C# 引擎与任务执行。R3 钩子和 R5 宿主替换是必须交付的实现工作，不再只做可行性评估。具体调用归属和迁移顺序见[引擎重写](upstream-engine-rewrite.md)。

产品组合已收敛为 **桌面 UI → Alas.Engine**、**浏览器 UI → Alas.Server → Alas.Engine**。Core 不在产品依赖图，也不作为 Engine 的业务代理或失败回退；旧源码仅作离线对照。Engine 自身承载规则、设备、导航、状态和业务执行，不再下接上游业务引擎。

当前配置与部署设置、Engine 队列及其报告已接入产品。按旧任务名运行、周期调度、统计、指挥喵服务和策略校验尚未迁入 Engine，接口明确返回不可用（HTTP 501）；它们是待完成能力，不能以切换引用视为迁移完成。控制入口的报告读取新 `engine-queue/1` 快照，旧报告与原生成功样本不算新引擎通过。

## 阶段门槛

### 伏击回避、迎击与途中战斗

此前 Engine 只识别伏击覆盖层与回避按钮，缺少后续处理。现 MapAmbushHandler 直接执行原生回避/迎击顺序：等待按钮、清理旧信息条、三秒点击节流、先匹配成功再匹配失败，未知信息清理后再判断是否进入战斗。失败回避和主动迎击使用 CombatFlow 的 no_searching 返回模式，按一秒/count=2 等待稳定地图；未知信息后发现的战斗保留普通寻敌等待。迎击按钮未点击时按低心情→退役顺序处理已有中断。素材参数和分支在 C#，Python 仅新增通用数值像素变换，不接收伏击业务或素材 id。

保持上游覆盖层与仅按钮两条入口的区别：覆盖层触发后读取 HP/等级，并在目标未到达时按原生等待补点；仅按钮入口不执行该前置读取和补点。到达确认优先于补点，伏击不调用 BOSS 出生镜头钩子、不增加地图战斗/塞壬数，也不消耗地图弹药。败方或缺失战果中止移动；伏击单独返回章节页不能证明通关，真正目标战斗仍须独立的成功结算证据。campaign_run / campaign_resume 接受 ambushEvade 布尔输入，默认 true。正常返回（含失败结果）的 ambushEncounters 保留逻辑舰队、目的格与观察帧/点击/伏击战果；它不证明目的格已到达。异常退出仍沿用已有异常/动作工件，暂不单独导出该列表。

### 诱饵敌人到达与重新选敌

此前 HasDecoyEnemy 只有配置和扫描器单测，战后扫描遗漏开关，空目标也被当作缺失战斗而中止。现 CampaignMapCombat 将普通扫描转为原生 decoy 模式，其他 init/movable/carrier 模式不被覆盖；观察合并可接收普通出生格以外的敌人。战斗预期从调用方按原生 combat、combat_siren、combat_boss、combat_fortress 或空 expected 传递，不再只由目标标记推断，因此 BOSS 候选、路障、救援和机关能保留各自门控与塞壬计数语义。

只有 HasDecoyEnemy 开启且 expected 为普通 combat 时，已确认无战斗的到达才清除假目标、更新舰队位置和路网，然后抛 MapEnemyMoved 重新选敌；不增加战斗数、塞壬数或消耗弹药，也不记为击破。确认沿用原生基础等待加一秒、count=6 的意外结果计时，并保留回合/机关附加等待；标记闪烁重新确认，延迟出现的真实战斗仍须胜方战果。回合推进及移动敌人重扫先于诱饵重新分派，部分重扫失败保留已确认位置但废弃本局状态。正常结果的 decoyArrivals 记录位置、逻辑舰队、战斗计数、等待阈值及依据帧；异常退出仍用现有异常/动作工件，暂不单独输出该列表。清理模式关闭诱饵，战役十次重新分派上界不变。

### BOSS 出生镜头恢复

此前章节的 RefocusBossAsync 已迁为 C# 方法，但战斗返回地图后没有调用，InMapCampaignOperations 仍抛占位异常。现由 MapCombatRecovery 按当前普通/loop 原始出生表检查下一场已完成战斗是否触发 BOSS，调用当前 CampaignRule 的真实钩子；章节预设优先于配置默认值。MapCamera 在同一锁与期限内刷新视图，仅几何识别失败时尝试非零滑动预设，再找边缘并返回动画前的机位。输入错误、陈旧帧、取消和超时不能触发预设补救，失败使相机与移动状态不可复用。

胜方战斗返回地图才进入恢复；返章节页、败方或缺失战果不调用出生钩子。恢复后按原生加权 HP 总和小于 .01 的条件重新读取，再继续到达确认。C# 的权威战斗计数仍在到达确认后提交，因此出生判断使用 BattleCount + 1；当前钩子看到的仍是未提交计数。已检查上游现有有效覆写只传静态预设，本项不声称覆盖未来依赖已递增计数的钩子。

### 塞壬同格救援与弹跳敌人

CampaignMapCombat 现直接迁移原生 fleet_2_break_siren_caught 与 clear_bouncing_enemy，InMapCampaignOperations 不再抛这两项占位异常。救援保留 BOSS 舰队角色、塞壬/移动开关与误报清理条件，按切换第二队→恢复相机边缘→同格战斗→扫描→切回第一队→清除抓取标记执行。仅有舰队到达标记不算救援成功；必须完成胜方战斗。候选 BOSS 被抓分支也使用第二队，不挪用第一队位置。回合重扫、返章节页或异常按原生顺序提前退出，不在 finally 强行切回。

### 迷宫路点等待

此前迷宫仅有声明和回合计算，移动仍直接拒绝。现由 CampaignMapCombat 在清敌、候选 BOSS、补给、谜题和机关的每个路点前调用原生 goto 对应的迷宫等待：当前相位激活时，在声明生成的 maze_nearby 中排除舰队，优先 is_enemy=False，再按 cost 选择邻格，通过实际 MapMovement 移动推进回合。保留原生十次上界和原始邻格集合，不按地图生成等待路线；三回合相位变化抛 MapEnemyMoved，现有战役循环重新分派。移动敌人回合优先执行重扫；普通等待不增加战斗数。

等待中的已知战斗、物品谜题和补给格复用现有交互合同；补给格保留额外确认点击，不进行显式 pick_up_ammo 的库存记账。非预期战斗按原生空 expected 语义，仅启用移动塞壬时归入 siren_count；该分支不同时标记普通敌人已清理。战斗返页保留原结果证据，不继续等待或虚增迷宫回合。章节 WalkUseCurrentFleet 直接控制到达判据，候选/已知 BOSS 战斗目标保留原生的当前标记禁用条件。正常战役结果的 mazeWaits 记录已确认邻格移动的来源、目标、前后回合、实际等待和帧号；失败前的状态不回滚，失败结果仍走现有异常工件，不能把标记或相位切换当作通关。

### 移动敌人回合与追踪

原来 MapMovement 对可移动敌人直接拒绝，战役寻路也未传入舰队步数。现在 MapRounds 在首次扫描后记录原生出生回合，普通移动确认后推进回合，战斗则先更新新出生批次；到达等待加入原生 round_wait，战斗返回地图后移除该等待但保留基础/机关等待。FleetRoles 按显示舰队与逻辑角色映射选取步数，战役的清敌、补给、谜题、机关及候选 BOSS 路径均使用这些路点。保留原生仅开启普通移动敌人时不推进回合的行为，不自行更改规则触发条件。

EngineSession 的移动工厂已组合 MapMovableScan 与现有 MapScanner。移动回合清理旧敌人标记，按原生队列与必扫点扫描，依次追踪塞壬及普通敌人，推断遮挡位置并刷新双舰队路径，然后由 CampaignExecution 重新分派；战斗数已增加时仍按原生结束当前战斗分派。墙体忽略、传送拓扑、舰队遮挡、空敌人模板时的侧面遮挡和静态遮挡保持原生语义，假设可达性查询不修改权威路径。正常结果的 movableScans 保存当前移动回合编号、移动前位置、扫描和匹配/预测记录；预测不等于独立观察或结算。动作不确定、重扫失败或退出地图后状态不可复用；已确认到达的位置和战斗记账不回滚，重扫失败不记录为完整扫描。

迷宫活动墙的路点等待与相位重新分派已接通，范围见上文。同格救援、弹跳与诱饵流程见上文；意外战斗恢复、完整活动规则及实机动态地图验收仍待完成，不因公共算法完成就扩大可执行 RuleCatalog 范围。移动等待超过本次行动期限也在点击前拒绝，不无限重试。

### 陆基机关执行

此前已迁移机关声明和 GridInfo 解除状态，但 MapMovement 仍拒绝机关格，ClearMechanismAsync 也只抛占位异常。现在通用战役操作按原生 `Map.clear_mechanism` 的启用条件、候选子集（空集合等同全部）、可达性及 weight/cost 顺序选择机关；沿现有路径移动，原生 mechanism_wait 加入到达确认计时，在新帧持续确认舰队到达后才解除同组触发点和阻挡并更新双舰队成本。普通移动中落在机关格同样处理，不依赖某张地图或单独点击脚本。解除后抛 MapEnemyMoved 让现有战役循环重新分派，纯机关操作不增加战斗数。

已有敌人或物品谜题占据触发点时，复用原有战斗/拾取合同；战斗返章节页保留战果而不伪造地图解除。兼有弹药标记的机关格保留原生到达补点，不执行 pick_up_ammo 的库存记账。异常关联、跨出击格子引用、非法等待或机关/传送门组合在动作前拒绝；输入失败、陈旧帧、页面中断、超时、取消不提前解除。正常战役返回时 `mechanismReleases` 记录触发位置、同组点、阻挡、确认时长与到达帧，只是按上游到达判据提交的规则状态，不是独立识别屏障消失或成功结算证据。

## 后端调用边界

`Alas.Engine` 是唯一产品业务后端。桌面通过 `DirectEngineBackend` 在进程内调用 `EngineControlWorkspace`；Server 使用同一工作区提供 API，浏览器经 `Alas.Client` 访问 Server。共享 UI 不引用 Engine、不固定 HTTP 传输；Server 不加载桌面 UI。`Alas.Engine.Cli` 直接组合 Engine；Core 已移出三个解决方案和产品引用。

## 长期不能变动的规则

- 战役加载、章节 Config、继承和钩子在 C# 中忠实迁移；原生实现只用于离线语义对照。
- 页面、按钮、弹窗、地图和视觉对象来自上游；禁止逐地图、逐界面独立适配。
- 导出 JSON 仅作离线展示、溯源和漂移校验，不替代上游运行时规则。
- 新域先实现 `ITaskRunner`，由 `TaskQueue` 调度；CLI 与前端不复制业务状态机。
- 通关只认结果合同；`CampaignEnd`、撤退、超时、单帧和威胁百分比都不能单独证明通关。
- Python 产品依赖仅限纯 CV/OCR；未经新执行图、性能及实机验收不得宣称完整重写完成。
- 完整约束与变更验证要求见 [AGENTS.md](../AGENTS.md)。
