# 整体迁移路线与不可变边界

本项目的目标是把 ALAS 的产品调度、任务域和关卡执行逐步迁移到 C#，同时保持上游规则和识图语义为唯一真值。后续开发按下面的顺序推进：

1. **先稳住契约链**：上游代码、素材和关卡数据通过同步脚本导出；JSON 只承担离线展示、来源追踪和漂移校验。每次上游更新都先完成导出校验，再进入运行时迁移。
2. **继续迁移通用运行时**：设备抽象、页面导航、任务调度、结果状态和错误诊断进入 `Alas.Core`；共享能力必须以接口和通用状态机表达，不能把某张地图的经验写成默认值。
3. **逐步替换宿主边界**：上层调用 `IVisionEngine` 和战役入口，不感知 Python 进程内/进程外实现。只有上游语义已经有等价 C# 实现、且对拍证据覆盖后，才允许替换对应宿主能力。
4. **最后迁移原生钩子**：按导出器报告的 `native_overrides` 和上游继承关系迁移通用钩子；迁移顺序由覆盖面和可验证性决定，不按单张地图打补丁。

以下规则是长期边界，后续提交不得改变其含义：

- 地图识别、章节配置合并、入口准备、相机恢复、战斗调度和结果判定继续复用上游调用链；生产路径必须经过 `CampaignRun.load_campaign()` 和上游 `Campaign.run()`。
- 不在 C# 适配层按地图名称、编号、尺寸或少数地图分组增加坐标、阈值、机位、路线、寻敌或战斗分支。发现失败先查完整调用链、状态清理和宿主兼容层。
- `data/*.json` 和 `assets.json` 不得成为运行时视觉或战斗规则的第二来源；运行时素材、页面和地图检测必须从上游模块对象解析。
- C# 图像参考实现只用于对拍和回归，产品识图必须通过 `IVisionEngine` 进入上游宿主。
- 真实通关必须以成功结算和返回章节页为准；撤退、超时、未知退出和单张截图均不能记为成功。
- 变更上述边界时，提交必须同时说明通用根因、保持的上游语义、影响范围和新增回归证据；没有这些证据不得改动稳定调用链。

无设备的架构守卫由 `tools/diagnostics/verify_architecture.py` 执行，并已纳入 `verify_all.py` 和 `sync_all.py --update --verify`。它检查生产入口、集中路径解析、素材模型完整性，以及地图特例和离线素材回流的静态违规。
