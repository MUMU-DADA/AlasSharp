# 迁移路线与当前状态

路线顺序：R0 真值与证据 → R1 常驻运行时 → R2 任务域 → R3 钩子评估 → R4 前端 → R5 宿主替换评估。
当前重点是 R2 剩余业务验证和 R4 统一界面；R3/R5 尚无满足门槛的迁移候选。

## 阶段门槛

| 阶段 | 当前成果 | 剩余工作与验收门槛 |
| --- | --- | --- |
| R0：真值与证据 | 冻结 `sortie-result/1`，Python/C# 对拍；归档主线、活动成功结算和本局撤退 | 其他结果分支仍需对应真实样本，不能从离线覆盖推断真机全覆盖 |
| R1：常驻运行时 | 单会话、取消、断点、逐任务工件和报告；队列观测与原生导航有真机样本 | 主战役地图内观测正样本、其他设备后端和平台验证 |

## R2 验证边界

- 主线统一流程有 1-1、1-4、2-1 成功结算样本；活动有 A1/A2/A3 样本，未覆盖的章节不据此推断。
- 原生导航有战术学院往返和待机恢复样本；旧 C# 导航器的逐跳记录不证明当前路径。
- `observe(map=os)` 有 4/4 抓帧与网格检出的真机正样本；主战役模式的主界面负样本不能代替地图内正样本。
- `reward` 有领取点击与奖励弹窗证据，但无独立到账数量读数；`dorm`、`freebies`、`tactical`、`meowfficer` 的调度样本不能一概视为领取、购买或补书成功。
- 已通关账号的大世界入口与调度有样本；要塞长战斗的通用接管修复已有离线回归，自动化成功结算闭环仍待验收。
- 未解锁“自律寻敌”的账号不满足上游大世界动作前提；入口超时不能据此外推为通用界面缺陷。

真机事实由[结果审计](archive/reports/result-evidence.md)和[队列审计](archive/reports/queue-evidence.md)生成；
识别覆盖见[识别总账](archive/reports/status.md)。历史轮次和性能调查见[归档](archive/README.md)。

## 下一步

1. 继续验证 Avalonia 共享界面：补复杂控件与性能，自动化统一使用原生 Headless；真实浏览器、系统输入法及各平台行为分别保留验收缺口，详见[统一 UI](r4-ui-architecture.md)。
2. 将共享 HTTP 客户端接入 UI 并补事件流，接通真实任务状态；编排继续复用 `QueueExecution`，保留 HTTP dry-run、边界停止和退出落盘回归。
3. 补远程认证与桌面生命周期，再分别验证 UI、无显示环境服务、Python 宿主及设备依赖的跨平台发布。
4. 按可用账号和设备窗口补 R2 真实业务证据；设备由主 agent 串行使用，失败先定位上游调用链。

## 长期不能变动的规则

- 战役必须使用 `CampaignRun.load_campaign()`、章节 `Config` 合并和原生 `Campaign.run()`。
- 页面、按钮、弹窗、地图和视觉对象来自上游；禁止逐地图、逐界面独立适配。
- 导出 JSON 仅作离线展示、溯源和漂移校验，不替代上游运行时规则。
- 新域先实现 `ITaskRunner`，由 `TaskQueue` 调度；CLI 与前端不复制业务状态机。
- 通关只认结果合同；`CampaignEnd`、撤退、超时、单帧和威胁百分比都不能单独证明通关。
- C# 图像实现只用于参考和对拍；未满足 R5 门槛不替换上游宿主。
- 完整约束与变更验证要求见 [AGENTS.md](../AGENTS.md)。
