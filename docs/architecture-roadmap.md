# 迁移路线与当前状态

最终目标：C# 执行全部非视觉逻辑，Python 仅保留必要的 CV/OCR 桥接。产品入口已切换到独立 Engine，完整业务重写尚未完成。
R0 证据、R1 运行时、R2 任务模型与 R4 UI 为现有基础；主线转为拆除产品路径的业务 Python 依赖、完成 C# 引擎与任务执行。R3 钩子和 R5 宿主替换是必须交付的实现工作，不再只做可行性评估。具体调用归属和迁移顺序见[引擎重写](upstream-engine-rewrite.md)。

产品组合已收敛为 **桌面 UI → Alas.Engine**、**浏览器 UI → Alas.Server → Alas.Engine**。旧 Core 已从仓库删除，不在产品依赖图，也不作为 Engine 的业务代理或失败回退；导出器和历史 oracle 仅作离线对照。Engine 自身承载规则、设备、导航、状态和业务执行，不再下接上游业务引擎。控制状态的运行活动使用 `engine-activity/1`，由 Engine 队列直接生成；生产状态不再发布旧 `scheduler` 字段。

当前配置与 Engine 自有设置、Engine runner 队列及其报告已接入产品。设置合同已替换旧上游部署 YAML，Server 和桌面 UI 直接使用 EngineSettingsWorkspace；ADB、CV runtime、OCR 模型目录在下一个队列创建时生效。旧安装/更新/OCR 服务配置及未实现的远程开关已退出设置 schema；启动列表仅保存偏好，自动启动调度未实现。统计、指挥喵服务和策略校验尚未迁入 Engine，接口明确返回不可用；旧任务名、周期调度和脚本入口已经移除。控制入口的报告读取新 `engine-queue/1` 快照，旧报告与原生成功样本不算新引擎通过。

地图初始化已在 Engine 内消费编译规则中的 `SwipePreset`，并接入潜艇定位。`MapSubmarineLocator` 直接迁移原生 `find_submarine` / `find_all_submarines`：无配置/无出生点、唯一初始观测、单出生点推定、唯一遮挡推定、多出生点逐点搜索和地图中心假设。镜头按当前位置重新选择最近候选，使用原生视野与离屏聚焦；推定位置不改写 `IsSubmarine` 观测。失败保留已检查点和当前待检查点，使本局状态不可复用；会话在任务边界清除证据。

### 移动步数不足恢复

### 航母谜题与增援扫描

### BOSS 路障与战中舰队切换

`MapRoadblocks` 直接迁移 `Fleet.brute_find_roadblocks` 的最少移除敌人数及地图枚举顺序，用带任意精度优先权的最短路取代指数级笛卡尔积。查询保留墙、单向传送门、陆地、机关及不可移除单位，不改变观测、逻辑舰队或成本场。`CampaignMapCombat` 接通 BOSS 清理、两舰队道路优先和候选出生点路障，实际出击只选最小集合中当前确实可达的敌人。原生同舰队搜索会遗留穿过已恢复敌人的假设成本，可能把较深的低权重敌人交给 goto；新路径按实际到达逐战提交并重扫。这是通用正确性收紧，不承诺复刻该错误下的整段点击轨迹，也没有逐地图补丁。

`CampaignFleetSwitcher` 按确认编号 → 新相机定位 → 双舰队成本 → HP → 非战后等级基线 → 画面舰队策略执行。相机丢弃旧舰队滑动记录，等待新帧上的舰队/当前标记，策略后再次恢复视图；保留另一队 HP 与既有等级触发标记。物理编号确认后立即提交身份，后续失败不回滚成旧舰队，并废弃该相机和切换控制器。任务级 `fleet-switch.json` 保存部分尝试，下一任务清空，报告拒绝丢失或自相矛盾记录。

此前两个移动工厂遗漏 `_goto` 每次外层尝试的 `fleet_ensure(fleet_current_index)`，而显式切队会跳过与内存编号相同的请求。现首次点击前及行走超时恢复后直接读取画面编号；编号正确时只同步新图，不刷新 HP、等级或几何，需要切队才执行完整恢复。伏击补点仍留在原生内层循环，不额外切队。`CurrentCheck=true` 标识同逻辑舰队确认；只有无切队点击且已确认编号时，Ready 才可不带新定位帧。读取、点击、同步或恢复失败使地图状态失效，禁止后续格子点击和位置提交。

`Alas.Engine` 是唯一产品业务后端。桌面通过 `DirectEngineBackend` 在进程内调用 `EngineControlWorkspace`；Server 使用同一工作区提供 API，浏览器经 `Alas.Client` 访问 Server。共享 UI 不引用 Engine、不固定 HTTP 传输；Server 不加载桌面 UI。`Alas.Engine.Cli` 直接组合 Engine；Core 已移出三个解决方案和产品引用。

## 长期不能变动的规则

- 战役加载、章节 Config、继承和钩子在 C# 中忠实迁移；原生实现只用于离线语义对照。
- 页面、按钮、弹窗、地图和视觉对象来自上游；禁止逐地图、逐界面独立适配。
- 导出 JSON 仅作离线展示、溯源和漂移校验，不替代上游运行时规则。
- 新域先实现 `ITaskRunner`，由 `TaskQueue` 调度；CLI 与前端不复制业务状态机。
- 通关只认结果合同；`CampaignEnd`、撤退、超时、单帧和威胁百分比都不能单独证明通关。
- Python 产品依赖仅限纯 CV/OCR；未经新执行图、性能及实机验收不得宣称完整重写完成。
