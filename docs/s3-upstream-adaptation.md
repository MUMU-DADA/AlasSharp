## 生产调用链

以下仍为旧产品的运行链。独立 `Alas.Engine` 的地图检测现已直接迁入 C#：类型化章节配置、线段筛选/拟合、单应性校准、中心/角点/轮廓分支及视野几何，与纯 CV 数值桥和 C# ADB 组合。通用根因修复包括 Hough 运算精度、灰度模板重复舍入、主地图/大世界 mask 使用位置及首次相机边缘校正，没有新增逐地图规则。原生对照、历史截图回放、队列/CLI 只读入口和失败证据通过，计数及命令见[迁移路线](architecture-roadmap.md)。这证明对应检测与离线调用语义，不证明真实移动、地图弹窗恢复或 C# 战役成功结算；旧 S3 生产链、冻结结果合同和既有成功证据未改写。

1. 以完整 `campaign.<目录>.<模块>` 读取 IR 并校验 `source`，不混用同名活动章节。真跑在创建设备前导入原生模块并检查 `Campaign.MAP`；源依赖缺失和辅助模块明确拒绝，dry-run 仍不导入业务模块。
2. 绑定 `Campaign_Name` 与 `Campaign_Event`，调用 `CampaignRun.load_campaign()` 合并章节及继承的 `Config`。
3. 清理设备 stuck/click 记录；上一局仍在地图内时先通过上游撤退，再导航。该清理撤退不参与本局通关判定。
4. 由上游 `ensure_campaign_ui()` 处理主线、困难、活动和档案入口，设置 `ENTRANCE`。
5. 调用实例原生 `Campaign.run()`，保留章节覆写、继承钩子、相机恢复与战斗调度。
6. 按[结果合同](result-contract.md)裁决并写入逐关工件，不从单个结束字段判断通关。

原生运行的可选影子观测限定于本次 `Campaign.run()`、当前线程和钩子选择日志，
通过响应中的 `shadow_observation` 传回 C#；不再按修改时间寻找并读取共享日日志。
旧实现会混入其他出击、覆盖同关重复尝试的影子工件，并可能因日日志被占用而中断批次索引写入。
现在影子工件跟随逐关工件的唯一名称，观测缺失、格式错误或落盘失败均告警并保留原始出击结论；
空观测和有跳过的观测不算一致，dry-run 不产生影子结论。变体从原生运行配置读取。
`verify_r5_observation.py` 覆盖当前运行隔离、被锁旧日志、重复尝试、故障和缺证据；
`verify_r5_host_contract.py` 使用原生无设备替身核对观测注册与释放。
这只证明已观测轮次的钩子选择，不证明原语动作等价、完整迁移或新增真机通关；
原生加载、入口、战斗调度、冻结结果合同和历史成功结算证据保持原样。

早期少行地图失败的通用根因是漏合并章节 `Config`，随后又发现手写入口/战斗循环遗漏上游流程。
现已移除阈值阶梯、画面放大、手写地图恢复和每轮额外 BOSS 扫描；不能把这些旧方案重新当成修法。

## 原生页面导航的过渡帧

用上游 `ui_page_appear()` 再次确认目标；无论正常或异常退出均恢复原点击方法。
页面图、素材对象、原生导航路线和服务器变体保持上游语义，没有新增页面坐标或分支。
